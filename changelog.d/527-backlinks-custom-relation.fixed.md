Backlinks now report the relation as written: each row carries `forward_relation` (what the source's file says), alongside `relation` (the target's reading) and `inverse_relation` (the declared inverse, `null` when the relation is custom). A custom relation such as `informs` is no longer hidden behind `related_to`. `pyrite link --bidirectional` with an unknown relation still writes `related_to` on the target, and now says so. Thanks to @berkay-byte for the diagnosis (#527, #562).
